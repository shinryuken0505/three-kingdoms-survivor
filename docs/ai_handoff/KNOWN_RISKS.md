# 已知風險與技術債

## 1. main.gd 過大

`scripts/main.gd` 同時承擔多種責任。任何修改都有跨系統副作用風險。

短期策略：以清楚註解、文件與區塊索引降低接手成本。

中期策略：從輸入與存檔開始漸進拆分。

## 2. 升級選單曾多次卡死

這是高優先回歸項目。不要只檢查 Space 判斷，還要檢查狀態、輸入鎖、候選資料與選擇函式錯誤。

## 3. 自我測試曾硬編碼章節

章節已超過早期範圍。所有測試必須動態讀取章節數量與最後一章。

## 4. Boss 流程有多階段狀態

Boss 死亡不是立即 victory：

```text
Boss死亡 → boss_loot → accept_boss_loot → victory → resolved
```

測試不得跳過戰利品階段。

## 5. 肖像歷史問題

曾出現 Alpha 與過深臉部陰影。新增或批次修圖後必須檢查：

- 尺寸
- Alpha
- 左右臉亮度差
- 裁切一致性
- UI 顯示效果

## 6. 缺少本環境 Godot Runtime

只做 Python 或文字掃描時，必須明確標記為「靜態檢查」，不可視為實機驗證。

## 7. 大型美術重製風險

地圖、碰撞、裝飾與敵人生成目前互相依賴。重繪地圖時應先保持碰撞資料不變，再逐章替換視覺層。
