# 測試與交付規範

## 測試分層

### A. 靜態檢查

```bash
python tools/project_structure_report.py
python tools/static_smoke_test.py
```

可以檢查：

- 必要檔案
- 主要函式是否存在
- 畫面狀態字串是否明顯缺漏
- 資產路徑與專案設定

不能證明：

- Godot 可成功解析所有 GDScript
- 實際輸入可用
- 戰鬥平衡正常
- 存檔流程完全正常

### B. Godot 啟動測試

使用 Godot 4.7.x 開啟專案，確認 Output 無紅字。

### C. 核心流程測試

最少測：

```text
新遊戲
→ 第一章第一次升級
→ 再次升級
→ 名將遭遇
→ 歷史事件
→ Boss
→ Boss戰利品
→ 章間整備
→ 更換裝備
→ 存檔
→ 返回主選單
→ 繼續遊戲
→ 第二章
```

### D. 輸入矩陣

每個 modal 都要測：

- Space
- Enter
- Numpad Enter
- 方向鍵
- WASD
- 滑鼠
- Esc

## 版本命名

- Patch：V1.8.0.1
- 小型功能：V1.8.1
- 大型系統／相容性變更：V1.9.0 或 V2.0.0

不要因為文件整理就直接宣稱 V2.0；大型版本必須有可感知玩法或架構里程碑。

## 交付說明必須包含

- 修改內容
- 未修改內容
- 靜態檢查結果
- 是否有 Godot 實機測試
- 已知風險
- 建議優先實測流程
